Problem Statement
Flaky tests don't fail because the code is wrong.
They fail because timing, ordering, and shared state are unreliable.
16% of all tests
Flakiness is universal at scale
Google measured ~16% of its own test suite as flaky. The best-resourced codebase on earth still has them, and so does yours.
5+ hrs / dev / week
Time lost chasing ghosts
Engineers routinely lose hours re-running pipelines and bisecting failures that were never actual bugs in the first place.
0 trust left
The suite stops meaning anything
After enough false alarms, teams reflexively ignore red — including the one failure that is a genuine production break.

Most tools can only point at flaky tests. Fixing by hand is slow, and the lazy fix — weakening the test — is worse than the flake itself. Minari is the only tool that closes the loop: detect, diagnose, fix, verify, and deliver.

Key technical decisions
✓
tree-sitter AST gate
Parse before any fix is accepted. Syntax errors are rejected at the source.
✓
HNSW vector search
768-d Gemini embeddings over past diagnoses. Recall similar failures instantly.
✓
Stateless + scalable
Each run is independent. Cloud Run scales horizontally; Redis holds shared limits.
✓
defusedxml + HMAC auth
XXE-hardened JUnit parsing. All inbound API calls verified with HMAC signatures.

Live SSE dashboard
